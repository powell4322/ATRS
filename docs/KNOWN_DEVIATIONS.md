# Known deviations and unresolved details

1. **Local ML-1M differs from paper tables.** The supplied SASRec text has 999,611 actions; BECOME reports 1,000,209. The text has no timestamps or raw ratings, so original filtering and timestamp ties cannot be checked. Paper absolute numbers are not direct validation targets.
2. **GRO backbone transfer.** The WSDM paper evaluates BERT4Rec. The current GRO implementation uses SASRec and has no accessible official-code comparison. Its swap gradient and joint objective follow Eq. 4-6 but hyperparameters are configured rather than externally verified.
3. **BECOME paper/source conflict.** In inspected official commit `83355ef`, `trainer/distiller.py` sets `beta = 1` inside the ranking loss. Its negative term is multiplied by zero although the paper's Eq. 23 describes a weighted ranking/negative objective. The unified implementation uses configurable `beta=0.5`; it is paper-oriented, not source-output equivalent.
4. **BECOME schedule and sampler.** The paper gives a normal-distributed phase length but does not fully specify its mean/variance. This code uses |N(1, 0.2)| normalized across phases and configurable 50% low-agreement selection. The official source uses a different hard-coded 9-round schedule and `alpha=0.75` in its sampler; the current unified configuration uses four phases and `alpha=0.5` to fit a near-20k actual-query cap. No numerical paper-native BECOME reproduction is claimed.
5. **Sim4Rec code absent.** No verified source for the AAAI extraction paper was located. The unrelated public project with the same name is a simulator. This implementation follows equations for CSG, MLE, listwise distillation, REINFORCE, and memory bank, but seed-query allocation, generator hidden size, reward normalization, and training interleave are engineering choices. Treat it as an exploratory comparator.
6. **Teacher training implementation.** The SASRec structure and 400-token ML-1M setting were checked against DFME/BECOME source, but this is a fresh PyTorch implementation rather than their exact modules. The reference dataset is generated from raw ratings, while this benchmark reads preprocessed text. The formal config uses batch 32 for GRO memory and a common backbone; paper training defaults use batch 128. Initializer details and optimizer grouping may differ slightly.
7. **Evaluation item filtering.** Unified full ranking removes already-seen history items, then restores the target. GRO's paper says full ranking but does not specify this masking in the provided text. Source `rankall` code may rank all item IDs without such filtering. This rule is applied identically to all unified cells and must be stated with results.
8. **Budget semantics.** The papers often report generated sequence counts; this benchmark counts every distinct prefix request. A 20k cap does not reproduce a 1k/3k/5k paper sequence budget. Caching may reduce requests below the configured cap. Results must include both counts.
9. **Resume and reuse.** Teacher resume is implemented. If an attack is interrupted, synthetic samples and generator optimizer state are not yet persisted for exact resume; the attack must restart. Reusing one query dataset with alternative losses is planned but is not part of current paper-method runs.
10. **No formal results yet.** Tests and smoke have passed. Converged teachers, multi-seed matrix, native paper reproduction, Steam/Beauty and BERT4Rec runs have not been executed.
