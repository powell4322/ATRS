## 早停、轮数与时间审查

| 对象 | 当前训练规则 | 早停与选择依据 |
| --- | --- | --- |
| Clean Teacher | 最多1000 epochs，Adam，100-step warmup 与线性衰减 | 防御方 valid NDCG@10；patience30，保存 best/latest |
| GRO Teacher | 共同 clean best 起点，最多追加1000 epochs，恒定 LR | 同样 patience30；轮数从追加训练重新计数 |
| Random / DFME Surrogate | 固定1000 epochs；当前没有早停 | 不读取真实 valid/test 选模型；只在完成后保存末权重并最终评价 |
| BECOME Surrogate | 初始20 + 7阶段×20 + 最后30，共190次阶段 epoch | 当前没有早停；各阶段样本规模不同，190不等于固定数据集的190次完整训练 |

“SASRec 在 ML-1M 上300轮内通常收敛”不能直接作为本次硬上限：本次 clean best 在319，300会截掉已观察到的最佳点。更重要的是，教师每轮只有80个 batch，而当前 Random/DFME 每轮有 ceil(1000×199/128)=1555 个 batch，约为19.44倍；教师和代理的 epoch 不能直接比较。

Random 最近10个完整 epoch 的耗时中位数为63.36秒，据此线性估计完整1000轮约17.60小时，快照之后剩余923轮约16.25小时。该值来自同一硬件的一段日志，不是新服务器或 DFME 的实测承诺。1000轮对应1555000次优化器更新。

训练 loss 从第20轮0.94774降到第50轮0.93103，再到第77轮0.92739，后段改善变慢；这不足以说明 Recall/NDCG/Agreement 已收敛。日志无负采样、forward、backward 的分项计时或 GPU 利用率，因此目前能确认的是代理总训练成本高，不能断言某个 kernel 是瓶颈。

教师记录的 seconds 包含训练与 validation，但不包含后续 checkpoint 写入等全部开销；代理 seconds 为从启动开始的累计时间。各段相加不等于精确实例计费时长。

## 后续每次完整任务

继续仅用 ML-1M + SASRec + seed42，保留 1k 名义序列、Top-100 与 Full Ranking。一次完整任务指预先选定的 cell 或诊断完成并保存产物，不要求一次租卡跑整个主矩阵。

| 顺序 | 完整任务 | 完成条件 |
| --- | --- | --- |
| 0 | 保留并复用现有 clean/GRO 教师，先审阅代理训练预算 | 原配置及四个教师 checkpoint 齐全；停止规则明确 |
| 1 | DFME × None/GRO 两格 | 同一攻击配置分别训练，得到五项真实主指标、查询账本与配对差值 |
| 2 | A 的预测性与 B 的四格机制诊断 | 明确 loss/LP/Exact 和监督/轨迹作用；作为独立研究任务，非服务器 smoke |
| 3 | 核心机制通过后，Ours × DFME | 用相同预算和训练规则与 None/GRO 比较 |
| 4 | BECOME × None/GRO/Ours | 检查自适应查询下的效果，保留原阶段机制 |
| 5 | 补充 Random，再决定扩展数据、模型与种子 | 不让补充对照阻塞机制研究；不自动启动完整矩阵 |

启动器默认已调整为顺序1的两格，命令仍只有 06 中的一个入口。预算尚保留当前1000轮；本轮没有提交一个未经验证的200/300轮替代配置。正式租卡前应先审阅顺序0的预算决策，避免将“任务顺序已调整”误解为“长轮数已经解决”。

当前服务器上的运行进程未被操作。本次 ZIP 中 Random 的77轮没有可恢复模型；若原服务器已经结束或停止，这些权重不能从 loss 日志重建。若还在运行，应以服务器实际文件为准，不因本地快照缺文件就擅自终止。

## 预算诊断与工程修改

后续停止标准的候选是预先固定 epoch/step 上限，或仅用独立合成前缀及 API 排序监督的验证指标。真实用户 valid/test 不得进入外部攻击早停。先设计一条连续训练曲线，在20/50/100/200等预定点保存状态、评估合成验证指标；不要把四个点都从头重训，也不要按最终 test 选择最佳 epoch。合成留出划分、验证指标、patience/min_delta 均为 TBD。

| 类型 | 本轮处理 | 是否改变学习机制 |
| --- | --- | --- |
| 已完成：教师复用 | 原配置 CPU resume 验证，无额外训练 | 否 |
| 已完成：任务编排 | 默认 DFME × None/GRO，不再先串行跑三个 GRO 攻击 | 只变执行顺序与当前所选格 |
| 已完成：终端显示 | 每 epoch 一行进度条、轮数和 loss；教师有 valid R/N，完成后打印五项主指标；JSONL 保留完整记录 | 否；未增加攻击阶段真实标签评价 |
| 已完成：轻量归档 | 快照摘要与验证效用进入 Git，明确标记未完成运行 | 否；不冒充完整防御结果 |
| 待修改：攻击中间保存 | Random/DFME 需要保存查询监督、模型、优化器、scheduler、全局及局部 RNG、loss/步数与来源，才能在 epoch 边界继续 | 工程恢复需专门测试；当前尚无 run-attack --resume |
| 待修改：BECOME 恢复 | 还需保存序列、阶段位置、频次、终端留出、反馈及 oracle 缓存/账本 | 不能只保存 Student 就称精确恢复 |
| 待验证：停止标准 | 同一攻击跨 None/GRO/Ours 统一，先校准再更新配置 | 会影响攻击强度；暂不修改 |
| 待测：分项性能 | 负采样/forward/backward/评价计时及 GPU 利用率 | 当前日志无法提供，不以 CPU 测试代替 GPU 吞吐 |

当前代码在攻击结束后才保存 Student 和查询集，保存了全局 RNG，但未保存局部 random.Random 的训练序列状态。因此“教师可接续”和“完整攻击 cell 可复用”不等于“中途攻击可恢复”。下一次长任务前应优先补保存/恢复，再开展学习曲线诊断；本轮依照先审查、避免核心重构的范围保留这一缺口。

若改变代理 epochs，线性 scheduler 的 total_steps 也会变化；不能简单把1000轮训练的前200轮称作独立200轮配置。当前整份配置 hash 还绑定教师：新建预算配置后需显式验证教师兼容性并记录复用来源，不能删掉身份检查来绕过。该预算切换接口尚待实现。
